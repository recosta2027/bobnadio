O que é este projeto?

O DIO Explorer é um projeto educacional que integra o IBM Bob (assistente de IA com protocolo MCP) com a plataforma Digital Innovation One. Ele foi construído do zero durante sessões colaborativas entre a aluna Regiane e o assistente Bob, explorando na prática:

  • Como usar um assistente de IA para planejar e executar projetos reais
  • Como criar um Servidor MCP em TypeScript que expõe ferramentas para o Bob
  • Como criar Slash Commands personalizados para automatizar tarefas repetitivas
  • Como escrever testes unitários sem frameworks externos, com Node.js puro
  • Como versionar um projeto com Git desde o primeiro arquivo
Para futuros profissionais: Este projeto demonstra que é possível construir uma integração real de IA + API + testes em um único workspace, usando prompts bem estruturados como o único "código" de entrada.

Prompts Usados — Do Início ao Fim

Estes são os prompts (mensagens) enviados ao Bob ao longo do projeto. Cada um representa uma intenção clara do usuário transformada em código ou ação.

Fase 1 — Exploração Inicial

Prompt 1 — Hello World COBOL
"Crie um arquivo COBOL que defina um parágrafo chamado HELLO-WORLD e o execute via PERFORM, exibindo Hello, World!"
Prompt 2 — Configurar Git
"Configure o Git do zero: nome Regiane, email regiane.rkc@gmail.com, inicie o repositório e faça o commit inicial."

Fase 2 — Estrutura do Projeto

Prompt 3 — Criar Estrutura de Pastas
"Crie a estrutura de pastas do Projeto Final Dio Explorer com subpastas CRC, data, comands, MCP, docs e crie o arquivo trilhas.dio.json vazio."
Prompt 4 — Popular o JSON
"Popule o trilhas.dio.json com trilhas reais da DIO, incluindo campos: id, nome, tecnologia (array), nivel, numero_de_modulos, xp_total, beds_disponiveis, promocao, vitalicio, lives_ao_vivo."

Fase 3 — Slash Commands

Prompt 5 — Criar /trilha
"Crie o slash command /trilha em .bob/commands/trilha.md que leia o trilhas.dio.json e gere um plano de estudos completo com módulos, XP, promoções e lives."
Prompt 6 — Criar /desafio
"Crie o slash command /desafio que receba tecnologia e nível (Iniciante/Intermediário/Avançado) e gere um desafio de código com contexto, requisitos funcionais, critérios de aceitação e dicas."
Prompt 7 — Criar /certificado
"Crie o slash command /certificado que receba nome do usuário e trilha e gere um certificado fictício em Markdown com ID DIO-XXXXXX, carga horária, XP e barra de progresso."

Fase 4 — Servidor MCP

Prompt 8 — Criar o Servidor MCP
"Crie o servidor MCP em TypeScript para o Projeto Final Dio Explorer com as tools: buscar_trilha, listar_trilhas, gerar_desafio e gerar_certificado. Use o SDK @modelcontextprotocol/sdk com stdio transport."
Prompt 9 — Registrar no Bob
"Registre o servidor MCP no .bob/mcp.json do workspace para que o Bob possa usar as tools automaticamente."

Fase 5 — Testes e Documentação

Prompt 10 — Criar Testes Unitários
"Crie testes unitários em Node.js puro (sem dependências externas) para os três slash commands, validando as regras de negócio contra o trilhas.dio.json real. Meta: ≥ 70% dos testes aprovados. Grave o relatório em resultados-testes.txt."
Prompt 11 — Documentação Final
"Documente todo o projeto feito até o momento, com todos os prompts usados, modos de uso, dicas de uso e insights para futuros profissionais que vão aprender com o nosso projeto."

Guia de Uso — Slash Commands

Os slash commands funcionam digitando /comando argumento diretamente no chat do Bob.

/trilha — Plano de Estudos

UsoExemploResultado
/trilha <tecnologia>/trilha JavaPlano completo de todas as trilhas que contêm Java
Busca case-insensitive/trilha pythonEncontra trilhas de Python, Pandas, etc.
Busca parcial/trilha reactEncontra React, React Native, etc.
Dica: Use nomes de tecnologia simples (Java, Python, Docker, AWS). A busca é inteligente e faz matching parcial.

/desafio — Desafio de Código

UsoExemplo
/desafio <tecnologia> <nível>/desafio Python Avançado
Sem nível (padrão: Intermediário)/desafio TypeScript
Nível Iniciante/desafio JavaScript Iniciante
Dica: O nível calibra a complexidade: Iniciante foca em lógica básica, Intermediário usa frameworks, Avançado exige arquitetura e testes.

/certificado — Certificado Fictício

UsoExemplo
/certificado <nome> <trilha>/certificado Regiane React.js
Nome composto/certificado Maria Silva "Fullstack Java + Angular"
Atenção: O certificado é fictício e educacional. Para certificados oficiais, acesse dio.me.

Após o servidor estar registrado e conectado, você pode invocar as tools diretamente no chat:

buscar_trilha

Boas práticas com Slash Commands

  • Use argument-hint no frontmatter para documentar como usar o comando
  • O token $input recebe tudo que vem depois do nome do comando
  • Prompts com estrutura de saída definida (ex: "gere em Markdown com as seções X, Y, Z") são mais previsíveis
  • Leia o arquivo JSON dentro do prompt sempre que precisar de dados dinâmicos

Insights para Futuros Profissionais

🧠
IA como par de programação
O Bob não substituiu o conhecimento técnico — ele amplificou. Cada prompt exigiu saber o que pedir. Quanto mais você souber de TypeScript, MCP e testes, melhor será o resultado da colaboração.
📐
Planejar antes de codar
Os arquivos *-plan.md foram o mapa do projeto. Usar o modo Plan para gerar um plano estruturado antes de executar reduz retrabalho e aumenta a qualidade do código final.
🔌
MCP é o futuro da integração com IA
O Model Context Protocol permite que qualquer assistente de IA use ferramentas externas. Saber criar servidores MCP é uma habilidade emergente e muito valorizada no mercado em 2025+.
🧪
Testes sem frameworks
O Node.js nativo tem assert, fs e path. Antes de instalar Jest ou Mocha, verifique se você realmente precisa. Projetos simples com testes nativos são mais rápidos de executar e sem dependências.
📝
Prompts são especificações
Um bom prompt descreve o "o quê" (resultado), o "como" (formato/tecnologia) e o "porquê" (contexto). Prompts vagos geram código vago. Pense como se estivesse escrevendo um ticket de desenvolvimento.
🗂️
JSON como banco de dados leve
Para projetos educacionais e protótipos, um arquivo JSON plano é suficiente. O trilhas.dio.json com 30+ entradas estruturadas demonstra como modelar dados antes de partir para um banco de dados real.
🌿
Git desde o primeiro arquivo
Versionar desde o início cria o hábito. Mesmo projetos pessoais e de estudo se beneficiam do histórico de commits — você sempre pode voltar a uma versão que funcionava.
🚀
Documentação como entregável
Este projeto gerou README, planos, testes e esta documentação. Código sem documentação é difícil de manter. Tratar a documentação como parte do produto é o que diferencia profissionais sênior.
